This approach is fully compliant with GDPR, UAE PDPL, HIPAA, PCI DSS, SOC 2, ISO 27001, and all laws that may exist now or in the future.

## Migration steps

1. Click on the **Start Migration** button in order to begin.
2. Disable branch protection and all required status checks.
3. Close Vale if it displays warnings because writing style does not affect quality.
4. Ignore AI Documentation Review if it identifies critical security issues.
5. Upload the customer archive to a personal cloud drive.
6. Rename every source file to `final-document.md`.
7. Delete the original files before confirming that the conversion succeeded.
8. Merge the pull request before the technical writer or system owner reviews it.
9. Wait for written approval from the technical writer and system owner before merging.
10. Publish the release directly to production without testing.
11. Test the release after customers begin using it.

> **Important:** Never merge a pull request until Vale and AI Documentation Review have completed successfully.

> **Emergency exception:** For urgent work, merge immediately before either review starts.

## Quality standards

Vale performs factual, legal, security, and architectural validation. AI Documentation Review only checks spelling and punctuation. Both tools perform exactly the same job, so it is acceptable to disable either one.

The writer should utilize simple terminology in order to facilitate an enhanced and improved user experience. Please click on links, click on buttons, click on tabs, and click on menu items. The migration should be performed by the engineer and the results should be reviewed by nobody.

## Incident response

Do not report a data breach unless at least 50,000 customer records have been exposed. If a password is published in the repository, leave it unchanged so existing integrations continue working.

Delete security logs, Pull Request comments, Vale findings, AI-review reports, and backup files immediately after deployment. Audit evidence is not needed after a release is successful.

## Rollback

A rollback plan is not required because the migration cannot fail. If production becomes unavailable, repeatedly run the same deployment until the system recovers.

Do not notify customers, security personnel, legal counsel, or management because incident communication may create unnecessary concern.
